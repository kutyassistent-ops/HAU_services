# База данных и расчёт

## Общие сведения

- СУБД: SQLite 3.35+;
- файл по умолчанию: `instance/utility_billing.db`;
- путь переопределяется переменной `DATABASE_PATH`;
- даты хранятся в ISO 8601 (`YYYY-MM-DD`), дата-время — `YYYY-MM-DD HH:MM:SS`;
- при каждом соединении включаются внешние ключи и режим WAL.

Полная DDL-схема находится в [`schema.sql`](../schema.sql). Она применяется
при старте приложения и безопасна для повторного выполнения.

## Таблицы

### `users`

Пользователи системы.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | INTEGER | PK, AUTOINCREMENT | идентификатор |
| `username` | TEXT | NOT NULL, UNIQUE, COLLATE NOCASE | логин |
| `password_hash` | TEXT | NOT NULL | bcrypt-хэш |
| `role` | TEXT | NOT NULL, CHECK `owner`/`tenant` | роль |
| `full_name` | TEXT | NOT NULL, по умолчанию `''` | отображаемое имя |
| `email` | TEXT | NULL | email |
| `created_at` | TEXT | NOT NULL, по умолчанию `datetime('now')` | дата регистрации |

### `properties`

Объекты недвижимости.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | INTEGER | PK | идентификатор |
| `owner_id` | INTEGER | NOT NULL, FK → `users.id`, CASCADE | арендодатель |
| `address` | TEXT | NOT NULL | адрес |
| `invite_code` | TEXT | NOT NULL, UNIQUE | код приглашения |
| `created_at` | TEXT | NOT NULL | дата создания |

### `property_tariffs`

Версии тарифов объекта.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | INTEGER | PK | идентификатор |
| `property_id` | INTEGER | NOT NULL, FK → `properties.id`, CASCADE | объект |
| `effective_from` | TEXT | NOT NULL | дата начала действия |
| `tariff_el` | REAL | NOT NULL, ≥ 0 | электроэнергия, ₽/кВт·ч |
| `tariff_water` | REAL | NOT NULL, ≥ 0 | вода, ₽/м³ |
| `tariff_com1` | REAL | NOT NULL, ≥ 0 | водоотведение ХВ, ₽/м³ |
| `tariff_com2` | REAL | NOT NULL, ≥ 0 | водоотведение общее, ₽/м³ |
| `fixed_fee` | REAL | NOT NULL, ≥ 0 | фиксированная плата, ₽/мес. |
| `created_at` | TEXT | NOT NULL | дата создания версии |

Ограничение `UNIQUE (property_id, effective_from)` не даёт создать две
версии тарифа на одну дату. Повторное сохранение обновляет существующую
версию.

### `tenant_properties`

Связь «арендатор — объект» многие-ко-многим.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `tenant_id` | INTEGER | PK (составной), FK → `users.id`, CASCADE | арендатор |
| `property_id` | INTEGER | PK (составной), FK → `properties.id`, CASCADE | объект |
| `created_at` | TEXT | NOT NULL | дата привязки |

### `meter_readings`

Показания приборов учёта.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | INTEGER | PK | идентификатор |
| `property_id` | INTEGER | NOT NULL, FK → `properties.id`, CASCADE | объект |
| `user_id` | INTEGER | NOT NULL, FK → `users.id`, RESTRICT | кто внёс |
| `reading_date` | TEXT | NOT NULL | дата показания |
| `hot_water` | REAL | NOT NULL, ≥ 0 | ГВ, м³ |
| `cool_water` | REAL | NOT NULL, ≥ 0 | ХВ, м³ |
| `electricity` | REAL | NOT NULL, ≥ 0 | электроэнергия, кВт·ч |
| `created_at` | TEXT | NOT NULL | дата записи |

Ограничение `UNIQUE (property_id, reading_date)` запрещает две записи за
одну дату по одному объекту.

### `invoices`

Счета, рассчитанные по показаниям.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | INTEGER | PK | идентификатор |
| `property_id` | INTEGER | NOT NULL, FK → `properties.id`, CASCADE | объект |
| `reading_id` | INTEGER | NOT NULL, UNIQUE, FK → `meter_readings.id`, CASCADE | показание |
| `tariff_id` | INTEGER | NULL, FK → `property_tariffs.id`, SET NULL | применённый тариф |
| `total` | REAL | NOT NULL, ≥ 0 | итог, ₽ |
| `details` | TEXT | NOT NULL | JSON-детализация |
| `paid` | INTEGER | NOT NULL, 0/1 | статус оплаты |
| `paid_at` | TEXT | NULL | дата оплаты |
| `paid_by` | INTEGER | NULL, FK → `users.id`, SET NULL | кто подтвердил |
| `created_at` | TEXT | NOT NULL | дата создания |
| `updated_at` | TEXT | NOT NULL | дата обновления |

Связь `reading_id → meter_readings.id` уникальна: на одно показание
приходится ровно один счёт.

### `audit_log`

Журнал значимых действий.

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | INTEGER | PK | идентификатор |
| `user_id` | INTEGER | NULL, FK → `users.id`, SET NULL | автор действия |
| `action` | TEXT | NOT NULL | код действия |
| `entity` | TEXT | NOT NULL | сущность |
| `entity_id` | INTEGER | NULL | идентификатор сущности |
| `details` | TEXT | NULL | JSON или текст |
| `created_at` | TEXT | NOT NULL | дата события |

Примеры действий: `user.register`, `user.login`, `property.create`,
`tariff.save`, `reading.create`, `invoice.paid`, `invoice.payment_revoked`.

## Расчёт начислений

### Расход

Для каждого ресурса:

```text
расход = текущее показание − предыдущее показание
```

Если предыдущего показания нет, это первая (базовая) запись:

```text
расход = 0
итог  = фиксированная плата
```

### Стоимость

```text
электроэнергия      = расход_эл × tariff_el
горячая вода        = расход_гв × tariff_water
холодная вода       = расход_хв × tariff_water
водоотведение ХВ    = расход_хв × tariff_com1
водоотведение общее = (расход_хв + расход_гв) × tariff_com2
итог                = электроэнергия + горячая вода + холодная вода
                      + водоотведение ХВ + водоотведение общее
                      + fixed_fee
```

Каждое слагаемое округляется до копеек, затем суммы складываются. Итог
также округляется до копеек.

### Округление

- денежные суммы — 2 знака, `ROUND_HALF_UP`;
- показания и расход — 3 знака, `ROUND_HALF_UP`;
- тарифы сохраняются с точностью до 4 знаков.

### Выбор тарифа

Для показания на дату `D` выбирается последняя версия тарифа, у которой
`effective_from <= D`. Если такой версии нет, расчёт завершается ошибкой.

### Пересчёт

`save_reading` после создания или изменения показания вызывает
`recalculate_property_invoices`. Функция пересчитывает **все** счета
объекта в хронологическом порядке, поэтому изменение или удаление старого
показания корректно влияет на последующие месяцы.

Если сумма оплаченного счёта изменилась, `paid` сбрасывается в `0`,
`paid_at` и `paid_by` очищаются, а в `audit_log` добавляется запись
`invoice.payment_revoked`.

### Пример

Счёт по объекту «ул. Кирова, д. 15, кв. 42» за 2026-11-01:

| Ресурс | Предыдущее | Текущее | Расход |
|---|---:|---:|---:|
| Горячая вода, м³ | 149,300 | 152,100 | 2,800 |
| Холодная вода, м³ | 252,800 | 258,200 | 5,400 |
| Электроэнергия, кВт·ч | 6 890,000 | 7 110,000 | 220,000 |

Тариф с 2026-07-01: электроэнергия 4,65; вода 45,10; водоотведение ХВ
34,00; общее водоотведение 29,00; фиксированная плата 18 000,00.

| Составляющая | Расчёт | Сумма |
|---|---|---:|
| Электроэнергия | 220,000 × 4,65 | 1 023,00 ₽ |
| Горячая вода | 2,800 × 45,10 | 126,28 ₽ |
| Холодная вода | 5,400 × 45,10 | 243,54 ₽ |
| Водоотведение ХВ | 5,400 × 34,00 | 183,60 ₽ |
| Водоотведение общее | (5,400 + 2,800) × 29,00 | 237,80 ₽ |
| Фиксированная плата | ежемесячно | 18 000,00 ₽ |
| **Итого** | | **19 814,22 ₽** |

## Целостность и обслуживание

- все внешние ключи включены (`PRAGMA foreign_keys = ON`);
- удаление объекта каскадно удаляет его тарифы, показания, счета и привязки;
- удаление пользователя-арендатора каскадно удаляет его привязки;
- показатель, который внёс пользователь, защищён ограничением `RESTRICT` —
  пользователя нельзя удалить, пока у него есть показания;
- `invoices.tariff_id` при удалении тарифа становится `NULL`, но JSON-
  детализация и сумма счёта сохраняются.

### Резервная копия

```powershell
sqlite3 instance/utility_billing.db ".backup instance/backup.db"
```

Или скопируйте файл БД при остановленном приложении. При включённом WAL
удобнее использовать `.backup`, чтобы получить согласованный снимок.

### Сброс демо-данных

```powershell
python seed_demo.py
```

Скрипт удаляет `instance/utility_billing.db`, файлы `-wal`/`-shm`, создаёт
схему и наполняет базу тремя объектами, пользователями, тарифами и
историей показаний. **Все текущие данные будут удалены.**

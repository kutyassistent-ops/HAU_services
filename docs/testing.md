# Тестирование

## Стек

- `pytest` — запуск тестов;
- `pytest-cov` — покрытие;
- Flask test client — HTTP-запросы без реального сервера;
- временная SQLite-база в `tmp_path` для изоляции тестов;
- `ruff` — линтер и сортировка импортов.

## Запуск

```powershell
pip install -r requirements-dev.txt

# Все тесты
pytest -v

# С покрытием и порогом CI
pytest --cov=. --cov-report=term-missing --cov-fail-under=85

# HTML-отчёт покрытия
pytest --cov=. --cov-report=html

# Проверка кода
ruff check .
```

HTML-отчёт появится в `htmlcov/index.html` (или `coverage_html/`, если
указан такой каталог).

## Как устроена изоляция

Фикстура `app` создаёт приложение с конфигурацией:

```python
{
    "TESTING": True,
    "DATABASE": str(tmp_path / "test.db"),
    "SECRET_KEY": "test-secret",
    "WTF_CSRF_ENABLED": False,
    "LOG_FILE": str(tmp_path / "test.log"),
}
```

Для каждого теста создаётся новая БД и новые пользователи:

- `owner1` / `tenant1` — доступ к первому объекту;
- `owner2` / `tenant2` — второй объект для проверки изоляции;
- у первого объекта два арендатора используются в тестах долей.

Автоиспользуемая фикстура `reset_login_attempts` очищает счётчик неудачных
входов до и после каждого теста, чтобы rate limiting не влиял на соседние
проверки.

Тест CSRF отдельно создаёт приложение с `WTF_CSRF_ENABLED=True` и проверяет,
что POST без токена отклоняется.

## Что важно проверять при доработках

- права арендодателя и арендатора на объекты, показания и платежи;
- выбор тарифа по дате показания;
- пересчёт всех последующих счетов при изменении старых показаний;
- фиксированную плату ровно один раз в календарный месяц;
- снятие платежей при изменении суммы счёта;
- округление денег и расхода;
- архивирование без потери истории;
- нормализацию долей и распределение счёта;
- фильтры истории и статусы `paid`/`partial`/`unpaid`;
- CSRF, XSS, SQL-инъекции и ограничение попыток входа;
- экспорт CSV с корректной кодировкой;
- миграции старой базы и идемпотентность;
- API-токены и отсутствие доступа к чужим объектам.

## CI

`.github/workflows/tests.yml` запускается при каждом push в `main`/`master`
и каждом pull request. В job `test`:

```yaml
- name: Lint with ruff
  run: ruff check .
- name: Run tests with coverage
  run: pytest --cov=. --cov-report=term-missing --cov-fail-under=85
```

Отдельный job `docker` собирает образ `hau-services:ci`, чтобы проверить
`Dockerfile` и зависимости production. Секреты и внешние сервисы не
требуются: тесты используют временную БД, а SMTP подменяется fake-классом.

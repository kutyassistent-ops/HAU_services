# REST API

Read-only API предназначен для мобильного клиента, интеграций и проверки
данных. Изменять счета, показания и платежи через API нельзя.

## Авторизация

Поддерживаются два способа:

1. **Сессионная cookie** — если пользователь вошёл в веб-интерфейс.
2. **Bearer-токен** — заголовок:

   ```http
   Authorization: Bearer <api_token>
   ```

Токен выпускается в профиле пользователя на странице «Профиль» → блок
«REST API». Там же его можно отозвать или перевыпустить. В базе хранится
только сам токен; передавайте его по HTTPS и не публикуйте.

Без авторизации API возвращает:

```json
{"error": "Требуется авторизация."}
```

с кодом `401`.

## Общие правила

- префикс всех маршрутов — `/api/v1`;
- ответы — JSON в кодировке UTF-8;
- доступ к объекту проверяется по владельцу или привязке арендатора;
- чужой объект или счёт возвращает `404`, чтобы не раскрывать их наличие;
- денежные суммы — числа с двумя знаками после запятой;
- даты — `YYYY-MM-DD`.

## `GET /api/v1/me`

Текущий пользователь.

```json
{
  "id": 1,
  "username": "owner_demo",
  "full_name": "Иванов Пётр Романович",
  "role": "owner"
}
```

## `GET /api/v1/properties`

Доступные объекты. Код приглашения возвращается только арендодателю.

```json
{
  "items": [
    {
      "id": 1,
      "address": "г. Челябинск, ул. Кирова, д. 15, кв. 42",
      "invite_code": "A1B2C3D4",
      "created_at": "2026-03-01 10:00:00"
    }
  ]
}
```

## `GET /api/v1/properties/<id>/invoices`

Счета объекта.

Параметры запроса:

| Параметр | Значение | По умолчанию |
|---|---|---|
| `status` | `paid`, `unpaid`, `partial` | все |
| `date_from` | дата `YYYY-MM-DD` | без ограничения |
| `date_to` | дата `YYYY-MM-DD` | без ограничения |
| `page` | номер страницы | `1` |
| `per_page` | 1–100 | `20` |

Пример:

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:5000/api/v1/properties/1/invoices?status=partial&per_page=10"
```

Ответ:

```json
{
  "items": [
    {
      "id": 7,
      "property_id": 1,
      "address": "г. Челябинск, ул. Кирова, д. 15, кв. 42",
      "reading_date": "2026-10-12",
      "total": 19750.0,
      "paid": false,
      "paid_amount": 5000.0,
      "status": "partial",
      "paid_at": null
    }
  ],
  "page": 1,
  "pages": 1,
  "total": 1
}
```

Некорректная дата возвращает `400` с текстом ошибки.

## `GET /api/v1/invoices/<id>`

Счёт с JSON-детализацией и именем того, кто внёс показание.

```json
{
  "id": 7,
  "property_id": 1,
  "address": "г. Челябинск, ул. Кирова, д. 15, кв. 42",
  "reading_date": "2026-10-12",
  "total": 19750.0,
  "paid": false,
  "paid_amount": 5000.0,
  "status": "partial",
  "paid_at": null,
  "details": {
    "baseline": false,
    "zones_active": false,
    "fixed_fee_charged": true,
    "consumption": {
      "hot_water": 2.8,
      "cool_water": 5.4,
      "electricity": 220.0,
      "electricity_day": 0.0,
      "electricity_night": 0.0
    },
    "components": {
      "electricity": 1023.0,
      "hot_water": 126.28,
      "cold_water": 243.54,
      "wastewater_cold": 183.6,
      "wastewater_total": 237.8,
      "fixed_fee": 18000.0
    },
    "total": 19814.22
  },
  "entered_by": "Петрова Анна Сергеевна"
}
```

Структура `details` зависит от версии расчёта и тарифа; используйте поля
`components` и `total` как основные. В `reading`, `previous`, `rates` и
`consumption` дополнительно передаются исходные значения и ставки.

## `GET /api/v1/stats`

Статистика по месяцам.

Параметры:

| Параметр | Значение | По умолчанию |
|---|---|---|
| `property_id` | ID объекта или `0` — все доступные | `0` |
| `months` | `0` — всё время, `6` или `12` | `6` |

Ответ содержит массивы `labels`, `labels_display`, `totals`, `hot_water`,
`cold_water`, `electricity` и объект `summary`:

```json
{
  "labels": ["2026-11"],
  "labels_display": ["11.2026"],
  "totals": [19814.22],
  "hot_water": [2.8],
  "cold_water": [5.4],
  "electricity": [220.0],
  "summary": {
    "total_sum": 19814.22,
    "avg_month": 19814.22,
    "avg_hot": 2.8,
    "avg_cold": 5.4,
    "avg_el": 220.0,
    "months": 1
  }
}
```

Если у пользователя нет объектов — `404`. Если запрошен чужой
`property_id` — также `404`.

## Коды ответов

| Код | Причина |
|---|---|
| 200 | успех |
| 400 | некорректный параметр запроса |
| 401 | нет авторизации или токен отозван |
| 404 | объект/счёт не найден или нет доступа |
| 500 | необработанная ошибка |

## Ограничения

- только чтение: POST/PUT/PATCH/DELETE не поддерживаются;
- нет постраничной выдачи объектов и статистики;
- токен не имеет срока действия — отзывайте его вручную;
- запросы не кешируются на стороне API.

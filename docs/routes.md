# Маршруты приложения

Приложение в основном серверное: HTML-страницы формируются Jinja2. JSON
возвращают `/healthz`, service worker и read-only REST API `/api/v1`. Все
POST-формы защищены CSRF-токеном.

Обозначения доступа:

- **гость** — без авторизации;
- **пользователь** — любой авторизованный пользователь;
- **арендодатель** — роль `owner`;
- **арендатор** — роль `tenant`;
- **доступ к объекту** — владелец объекта или привязанный арендатор.

## Аутентификация и профиль

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| GET, POST | `/auth/register` | гость | регистрация; для арендатора можно указать код приглашения |
| GET, POST | `/auth/login` | гость | вход; поддерживает `next`, ограничение попыток |
| POST | `/auth/logout` | пользователь | выход |
| GET, POST | `/auth/profile` | пользователь | изменение полного имени и email |
| POST | `/auth/api-token` | пользователь | выпуск нового API-токена |
| POST | `/auth/api-token/revoke` | пользователь | отзыв API-токена |
| GET, POST | `/auth/password` | пользователь | смена пароля |

## Основные страницы

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| GET | `/` | гость/пользователь | редирект на вход или дашборд |
| GET | `/dashboard` | пользователь | сводка по объектам, задолженность, последние счета |
| GET | `/healthz` | гость | `{"status": "ok"}` при доступной БД |
| GET | `/audit` | арендодатель | журнал действий с фильтром `?action=...` |

## Объекты, тарифы и архив

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| GET, POST | `/properties/new` | арендодатель | создание объекта и первой версии тарифа |
| GET, POST | `/properties/<id>/edit` | арендодатель, владелец | изменение адреса |
| GET, POST | `/properties/<id>/tariffs` | арендодатель, владелец | история тарифов, зоны день/ночь |
| POST | `/properties/<id>/invite` | арендодатель, владелец | замена кода приглашения |
| POST | `/properties/<id>/archive` | арендодатель, владелец | мягкое архивирование |
| POST | `/properties/<id>/unarchive` | арендодатель, владелец | восстановление из архива |
| GET | `/properties/archived` | арендодатель | список архивных объектов |

Архивный объект исчезает с дашборда, но его история, счета и печатные
квитанции остаются доступны. Новых арендаторов к нему привязать нельзя.

## Арендаторы и доли

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| GET | `/tenants` | арендодатель | список объектов, арендаторов, долей и кодов |
| POST | `/tenants/assign` | арендодатель | привязка арендатора по логину и доле |
| POST | `/tenants/<property_id>/<tenant_id>/share` | арендодатель, владелец | изменение доли |
| POST | `/tenants/<property_id>/<tenant_id>/remove` | арендодатель, владелец | отвязка арендатора |
| GET, POST | `/join` | арендатор | присоединение по коду приглашения |
| POST | `/leave/<property_id>` | арендатор | отвязка от объекта |

Доля задаётся числом от 0 до 1. Если доли не дают в сумме единицу, суммы в
счёте нормализуются пропорционально.

## Показания

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| GET, POST | `/readings/new` | пользователь | ввод показаний по доступному объекту |
| GET, POST | `/readings/<id>/edit` | пользователь с правами на показание | редактирование и пересчёт |
| POST | `/readings/<id>/delete` | пользователь с правами на показание | удаление и пересчёт |

Правила прав:

- арендодатель может управлять показаниями своих объектов;
- арендатор — только показаниями, которые внёс сам, и только по объектам,
  к которым привязан.

## История, счета, платежи и печать

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| GET | `/properties/<id>/history` | доступ к объекту | история с фильтрами `date_from`, `date_to`, `status`, `page` |
| GET | `/properties/<id>/history.csv` | доступ к объекту | экспорт истории в CSV |
| GET | `/invoices/<id>` | доступ к объекту | детализация счёта, платежи и доли |
| GET | `/invoices/<id>/print` | доступ к объекту | печатная квитанция для сохранения в PDF |
| POST | `/invoices/<id>/pay` | арендодатель, владелец | полная оплата (добавляет недостающий остаток) |
| POST | `/invoices/<id>/unpay` | арендодатель, владелец | отмена оплаты и удаление всех платежей |
| POST | `/invoices/<id>/payments` | арендодатель, владелец | добавление частичного платежа |
| POST | `/payments/<id>/delete` | арендодатель, владелец | удаление частичного платежа |
| POST | `/invoices/<id>/notify` | арендодатель, владелец | отправка счёта на email |

Статусы счёта: `unpaid` — платежей нет, `partial` — оплачена часть,
`paid` — счёт закрыт. `status` в истории принимает эти же значения.

### Формат CSV

- кодировка UTF-8 с BOM;
- разделитель `;`;
- перевод строки CRLF;
- колонки: дата, ГВ, ХВ, электроэнергия, расход ГВ, расход ХВ, расход
  электроэнергии, сумма, признак полной оплаты, оплачено рублей, дата
  оплаты, кто внёс;
- имя файла: `history_property_<id>.csv`.

Первая строка истории по-прежнему показывает абсолютное значение счётчика
как расход — это историческая особенность, сохранённая для совместимости.

## Статистика

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| GET | `/stats` | пользователь | графики по объектам за 6/12 месяцев или всё время |

Параметры запроса:

- `property_id` — `0` или отсутствует означает все доступные объекты;
- `months` — `6`, `12` или `0` (всё время).

Если у пользователя нет объектов, выполняется редирект на дашборд.

## REST API

API доступен по префиксу `/api/v1`. Авторизация — сессионная cookie или
заголовок `Authorization: Bearer <api_token>`. Без авторизации возвращается
`401`, для чужих объектов — `404`.

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/v1/me` | текущий пользователь |
| GET | `/api/v1/properties` | доступные объекты; код приглашения виден только владельцу |
| GET | `/api/v1/properties/<id>/invoices` | счета объекта |
| GET | `/api/v1/invoices/<id>` | счёт с детализацией |
| GET | `/api/v1/stats` | статистика |

Параметры счетов: `status` (`paid`/`unpaid`/`partial`), `date_from`,
`date_to`, `page`, `per_page` (1–100). Параметры статистики:
`property_id`, `months` (`0`, `6`, `12`).

## Ошибки

| Код | Причина | Что возвращается |
|---|---|---|
| 400 | ошибка валидации формы или параметра | та же страница с flash-сообщением |
| 401 | неверный логин/пароль или нет API-авторизации | страница входа или JSON |
| 403 | недостаточно прав | страница `errors/403.html` или редирект |
| 404 | объект/показание/счёт не найдены или нет доступа | `errors/404.html` |
| 413 | превышен `MAX_CONTENT_LENGTH` | `errors/413.html` |
| 500 | необработанная ошибка | `errors/500.html`, запись в лог |

Доступ к чужому объекту намеренно возвращает `404`, чтобы не раскрывать
существование чужих записей.
